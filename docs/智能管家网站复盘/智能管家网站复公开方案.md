# FamilyCare AI 通用规则与个人生活成长功能方案

更新日期：2026-10-12

本文件用于说明产品规则、功能范围及开发顺序，不包含任何用户个人数据。此次仅更新文档，不发布本地未提交代码，也不代表规划中的功能已经实现。现有稳定版本标签保持不变。

## 一 产品方向

在家庭健康记录基础上，规划个人生活与成长档案。用户通过文字、语音转文字或图片表达，系统按日期整理可追溯的记录，支持生活复盘、目标跟踪及选择比较。

家庭健康管理与个人成长内容采用独立可见范围。个人偏好、工作经历和私人决策默认仅本人可见，分享时由本人选择范围。

## 二 已有能力与规划边界

既有项目包含多成员健康档案、每日反馈、时间线、就医摘要、资料管理和医学依据展示。应区分仓库发布版本、本地开发版本与尚未实现的设计，不把本地验收结果当成线上服务承诺。

本地开发记录涉及统一健康入口、批量原件保存、人工核对入档和后台飞书存档；本次不上传这些代码。真实 OCR、飞书机器人消息、完整恢复和实体手机访问仍需专项验收。

下列生活与成长功能均为待开发方案。已有小智适配代码继续保留，小智只是可选输入终端。

### 日常记录流程

用户表达 → 明确所属成员与日期 → 保存原话和附件 → 提取记录草稿 → 必要时核对 → 更新档案与时间线 → 形成周期复盘。

健康内容复用医疗安全入口；普通生活内容按自身规则整理，避免把工作或兴趣记录误当成症状。缺少信息时标记待补充，不虚构日期、份量或结果。

### 饮食记录流程

饭前拍照 → 饭后拍照或选择全部吃完 → 补充食物名称与大致份量 → 查看估计并修改 → 保存同餐记录。

两张照片需属于同一餐，记录加菜、续饭、分享食物和遗漏的饮料等情况。照片用于估计摄入，不用于计算身体实际吸收量。油、重量及隐藏食材难以从图片可靠判断，应显示范围和估计依据。包装营养标签、菜单、称重信息可提高可信度，首版不要求每餐称重。

目标观察结合带日期的体重、饮食、运动、睡眠及胃肠反馈；营养数据库需注明来源及版本，不根据估计值自动开药或调整治疗。

### 学习与选择流程

学习时间和自评作为背景，实际成果、完成难度、独立程度及后续反馈作为能力判断依据。系统可建议探索方向和短期试验，不对职业前景或人生结果作确定性预测。

决策记录保留当时的理由、约束和预期，后续追加实际结果，用于改善下一次比较；不要按事后结果改写当时的判断。

## 四 通用规则

1. 当前成员必须明确，涉及其他家人时先确认归属，不写入当前成员。
2. 保存原话、记录时间、发生时间、入口来源和附件关联，修改保留历史。
3. 区分当前、历史、已缓解、否定、假设、提问和转折。例如“最近没有黑便”不触发当前黑便提醒；“没有黑便，但今天便血”应识别后半句。
4. 就医前确认原医生复诊或新医生初诊。原医生优先近期变化精简版，新医生提供相关既往史；医生关系未知时保持待确认。
5. 长期档案与每日变化分开。报告需按发生日期组织，明确近期消失、新发及既往情况。
6. 医疗资料先保存原件，识别结果进入待确认状态，人工核对后才成为正式事实；低置信度需单独核对。
7. 历史检查日期与上传日期分开；旧报告异常不得直接生成今天的风险。
8. 用户确认的事实与系统推测分开。性格或偏好推测需列依据、日期和确认状态，可以被纠正，不据少量记录固定标签。
9. 不同入口复用健康业务规则，重复提交与消息重试避免重复入档。
10. 系统帮助记录、观察及就医沟通，不自行诊断、开方、停药或调整剂量。

## 五 本地 MD 与系统数据

规划将全部文字记录、确认内容、分析依据和版本历史持续沉淀到本人本地 MD。首版采用一份个人主档案，按日期追加，图片和报告原件作为关联附件。MD 包含基础档案、偏好、目标、每日记录、学习成果、周期复盘和决策记录。

本地 MD 为可独立阅读、可迁移的资料；网站数据库提供检索、关联和页面展示。实现时明确统一写入与同步规则，使用记录 ID 和修订版本，避免 MD 与数据库各自成为相互冲突的事实来源。同步失败保留本地待办，发现冲突保留双方版本并要求核对。

用户本人资料可存入其配置的智能管家与家庭飞书空间。家庭飞书与个人私密成长内容须明确访问边界，不能因为一个家庭共用账号就默认实现成员级隐私隔离。

GitHub 只保存代码、通用规则、配置模板和无个人数据的方案。姓名、病历、饮食照片、每日反馈、体重、药物记录、数据库、个人 MD、附件及凭证均不随项目文档发布。

## 六 开发顺序

### 第一阶段 记录与沉淀

统一生活记录入口，完成原话与附件保存、偏好确认、本地 MD 沉淀、网站查询和每周复盘。先验证用户能持续记录，再增加复杂分析。

验收重点：记录能找回，成员与日期正确，原文可追溯，修改有历史，导出与系统记录一致。

### 第二阶段 饮食与目标

完成同餐饭前饭后配对、份量修正、营养范围估计、估计依据和目标趋势关联。

验收重点：照片误配可修正，油和份量不确定性可见，摄入与吸收明确区分，未知数据不会显示为零。

### 第三阶段 成长与选择

完成学习成果档案、能力证据、选项比较、小规模试验与事后复盘。

验收重点：建议能追溯到实际记录，资料不足时明确不确定性，系统不替用户确定性格、职业路线或未来结果。

## 七 近期优化优先级

优先完善一键启动和运行状态提示，真实报告识别与核对，处方和每日反馈关联，独立测试数据库备份恢复演练，最后完成安全手机访问及飞书机器人身份绑定。

当前只记录本轮已描述的生活与成长方向；未提出的第二项需求保持空缺，不自行扩展。开发前再结合实际使用反馈确定首版范围。
