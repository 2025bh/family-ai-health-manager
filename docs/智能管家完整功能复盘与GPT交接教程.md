## 一、先看结论：这是一个什么产品

这是一个在 Windows 本机运行的家庭长期健康记录和就医准备网站。

它的核心目标不是“让 AI 看病”，而是：

1. 本人或家人用自然语言记录每天的身体变化。
2. 系统永久保留原话，同时整理出睡眠、胃肠、排便、情绪、运动、用药反应和测量数据。
3. 把长期记录形成可搜索、可筛选的时间线和近期趋势。
4. 看医生前按医生关系生成合适的就医摘要。
5. 看医生后记录医生意见和复查任务。
6. 出现明确安全风险表达时优先提醒就医，不继续普通聊天。

产品原则：

- 聊天产生数据，而不是为了数据聊天。
- 让家人负责说，让 AI 负责记，让医生更容易看懂。
- 不自行诊断疾病，不开药，不建议停药、换药或调整剂量。
- 个人健康资料默认保存在本机，不自动上传给外部 AI、飞书或其他平台。

## 三、用户、主流程和产品载体

### 当前用户

- 当前主要真实测试用户：黄金周。
- 系统也支持爸爸、妈妈、爷爷等多个家庭成员。
- 首页会记住本机上一次选中的成员，避免每次重新选择。
- 新建记录前必须确认当前成员，防止把某位家人的症状写到另一位名下。

### 当前载体

- 主要载体：本地网页。
- 后端：FastAPI + SQLAlchemy + SQLite。
- 前端：React + TypeScript + Vite。
- Android：只有基础伴侣端工程，尚不是正式可用 App。
- 小智硬件：已有接口边界，尚未真实接入语音设备。

### 主流程

```text
选择家庭成员
  → 自然语言记录今天情况
  → 保留原话并结构化整理
  → 医疗安全语义判断
  → 写入本地数据库
  → 最近7天摘要 / 7天或30天趋势 / 长期时间线
  → 看医生前核对并生成摘要
  → 看医生后记录反馈和复查任务
```

## 四、当前网站页面和全部功能

### 1. 今日工作台

地址：`http://127.0.0.1:5173/`

已经具备：

- 显示当前选中的家庭成员。
- 快速切换家庭成员，并记住上次选择。
- “记录今天”主入口。
- 显示今天待完成的健康任务。
- 快捷进入准备复诊、中药疗程和检查资料。
- 显示最近7天健康摘要。
- 显示“今日健康守护”。
- 可展开网页文字版“小智健康管家”补充说明。
- 加载失败时显示真实错误和重试入口，不把失败伪装成“没有异常”。

### 2. 每日健康记录 / 小智文字对话

地址格式：`http://127.0.0.1:5173/daily-log/成员ID`

已经具备：

- 可以自然输入症状、睡眠、饮食、运动、情绪、排便和用药反应。
- 永久保存用户原话。
- 同时保存结构化结果，例如日志类型、症状、持续时间、睡眠信息等。
- 保存后展示系统提取到的字段。
- 可以点击“修改刚才记录”，修正原始记录。
- 修改前版本保存在修订记录中，不直接覆盖而不留痕。
- 修改后重新解析，并重新计算7天和30天趋势。
- 他人的症状不会写入当前成员。
- 假设句和纯健康提问不会被误写为当前症状。

自然语言示例：

```text
昨晚三点多醒了，五点才睡着，今天人有点软。
中午吃完饭有点胀，晚上散步后舒服些。
今天排便正常，没有黑便，也没有便血。
今天体重49.8公斤。
```

### 3. 健康测量

可以通过文字记录：

- 血压，例如：`今天血压118/76。`
- 血糖，例如：`今天血糖8.1。`
- 体温，例如：`今天体温37.2。`
- 体重，例如：`今天体重49.8公斤。`

血糖缺少测量场景时，系统只追问一个问题：空腹还是饭后。回答后再保存。

边界：

- 系统记录原值、单位和测量场景。
- 不能根据一次家用测量直接诊断糖尿病。
- 不能根据单次数值自行调整药物。

### 4. 个人健康档案

地址格式：`http://127.0.0.1:5173/members/成员ID`

已经具备：

- 基础信息：性别、年龄、身高、体重、职业等。
- 已知健康问题。
- 当前长期用药。
- 当前主要表现。
- 长期健康管理重点。
- 近30天记录数量。
- 进入每日记录和看医生模式的快捷按钮。

健康档案是“不经常变化的基础资料”；每天的身体反应应进入健康日志，不应继续混在基础档案里。

### 5. 长期健康时间线

位于个人健康主页下方。

时间线合并展示：

- 健康日志。
- 血压、血糖、体温和体重测量。
- 就医记录。
- 健康任务。
- 检查资料。
- 中药疗程。

筛选能力：

- 关键词搜索，例如失眠、腹泻、遗精。
- 按数据类型筛选。
- 最近7天、最近30天或全部时间。
- 只看需要提醒医生的异常。
- 按日期折叠。
- 每次显示25条，继续点击再加载，避免长时间线一次全部展开。

### 6. 最近7天健康摘要

首页自动汇总以下类别：

- 睡眠。
- 胃肠与排便。
- 精力。
- 体重。
- 血压。
- 血糖。
- 情绪。
- 口腔。
- 遗精 / 性健康。
- 用药变化。
- 其他记录。

一条长日志可以同时进入多个相关分类，但每个分类只截取对应短句，避免整段日记反复复制。

### 7. 现代医学健康守护

地址格式：`http://127.0.0.1:5173/health-guard/成员ID`

当前默认开启，已经具备：

- 最近7天与上一周期比较。
- 最近30天与上一周期比较。
- 胃肠、排便、睡眠、体重、情绪、饮食、运动、用药反应、血压、血糖、体温和其他症状分类观察。
- 四种结果：数据暂不足、继续观察、值得关注、建议及时处理/就医。
- 展示“为什么这样判断”。
- 展示使用了哪些本人数据。
- 展示仍需确认的信息。
- 展示下一步建议。
- 展示规则编号、分析版本和证据来源。

重要边界：

- 趋势表示“记录发生频率或测量变化”，不是疾病诊断。
- 数据不足时必须显示数据不足，不能强行给绿色正常结论。
- 红色安全提醒优先于普通趋势。

### 8. 医疗安全语义层

这是独立于大模型的确定性安全层，始终优先运行。

它会区分：

- 当前发生还是历史发生。
- 本人还是其他家人。
- 肯定、否定、恢复、假设或提问。
- 转折前后是否出现新症状。

已经验证的例子：

- `今天突然出现黑便`：触发当前红色风险。
- `最近两周没有黑便，也没有便血`：不触发当前风险。
- `之前黑便，现在已经没有了`：识别为已恢复。
- `没有黑便，但是今天出现便血`：仍触发当前红色风险。
- `我爸爸今天黑便`：不写入当前成员，要求切换成员。
- `如果以后出现黑便怎么办`：视为提问，不写成当前症状。

当前保守红旗示例包括：呼吸困难、剧烈胸痛、部分神经系统急症表达、大量出血/黑便/便血/呕血、剧烈腹痛/绞痛、自伤表达。

这些规则目前仍属于产品安全基线，正式临床使用前必须经过医学专业人员审核。

已经具备：

- 显示处方日期、医生、医院科室、服法和换方关系。

### 11. 检查资料和病历原图

地址格式：`http://127.0.0.1:5173/documents/成员ID`

已经具备：

- 上传 PDF、PNG、JPG、JPEG、WebP。
- 选择资料类型：化验单、处方、影像、医嘱单等。
- 记录检查日期。
- 填写家属摘要。
- 根据资料类型筛选。
- 使用中文标题显示资料。
- 图片列表加载轻量缩略图，不直接加载全部原图。

隐私规则：

- 原始病历和处方文件保存在本机。
- 飞书只允许同步摘要和索引，不上传原始医疗文件。
- 当前默认文档解析器为模拟模式，不能宣称已经完成可靠 OCR 或处方识别。

### 12. 看医生模式

地址格式：`http://127.0.0.1:5173/doctor-mode/成员ID`

流程：

1. 点击“准备看医生”。
2. 系统先问这次是原医生复诊还是新医生/换医生。
3. 每次只问一个问题，共整理医生关系、主要问题、开始时间、近期趋势、明显场景、伴随症状、用药变化和最想问医生的问题。
4. 回答结束后不直接生成正式报告，先进入核对页。
5. 核对8个回答、近14天原始记录、已知病史、长期用药和近期敏感症状。
6. 可以修改某一项。
7. 确认无误后生成正式摘要。
8. 可以打印 A4 版并标记“已给医生看”。

### 13. 原医生复诊与新医生初诊分流

这是强制产品规则，不能丢失：

- 每次生成就医报告前，都必须询问医生关系。
- 如果是原医生，还要确认医生姓名。
- 不能因为上一次看的是某位医生，就自动假设本次还是原医生。

原医生复诊：

- 默认生成近期精简版。
- 重点写最近一至两周变化、总体趋势、当前遗留问题、近期用药变化和本次要确认的问题。
- 不重复整套既往史和全部检查资料。

新医生初诊或换医生：

- 默认生成详细版。
- 包含已知病史、重要检查、完整用药疗程、症状时间线、历史安全关注和当前问题。

历史异常处理：

- 必须带实际日期。
- 如果近期未再出现，应明确写“历史曾出现，最近观察期未再出现”。
- 不能把旧黑便、偏红便等历史异常写成当前症状。

### 14. 遗精 / 性健康信息完整性

系统已固化以下整理规则：

- 睡觉时射了、半夜射精、无意识射精、梦遗和遗精，在明确睡眠/夜间语境中统一整理为“睡眠中遗精”。
- 同时永久保留用户原话。
- 就医核对清单要单独检查近期敏感症状，避免因为用词口语化而漏掉。
- 只记录时间、次数和伴随感受，不自行诊断原因，不自行调整药物。
- 跨午夜难以确定日期时，写“某日晚、临近次日”，不擅自改成次日白天。

### 15. 就医报告核对、打印和标记

报告核对页已经具备：

- 修改某个回答。
- 查看近14天原始分类记录。
- 单独列出近期敏感症状。
- 查看既往健康问题和长期用药。
- 确认后生成正式报告。
- 打印核对清单。

正式报告已经具备：

- 手机阅读版和 A4 打印版。
- 主要问题、近期反馈、既往问题、近期用药、检查资料和想问医生的问题。
- 标记“已给医生看”。
- 明确信息来源和“不构成诊断或用药建议”。

### 16. 就医后记录

使用方式：

我看完医生了。

### 21. 西医知识与医学依据

地址：`http://127.0.0.1:5173/medical-knowledge`

已经具备：

- 展示知识编号、主题、标准说明、审核提醒和官方来源。
- 显示总条数、待复核条数和参与自动分析的条数。
- 官方资料统一保存在 `docs/医学依据待审核/`。
- 当前已保存 NICE 的胃肠、胸痛、自伤安全指南及国家卫健委/NICE 的糖尿病资料。

糖尿病专题当前有6条知识：

1. 家族史表示风险增加，不等于本人确诊。
2. 家用血糖测量与医疗筛查/诊断必须区分。
3. 饮食和运动建议必须个体化，体重偏低者不能自动套用减重建议。
4. 已确诊2型糖尿病后的复查频率应结合治疗稳定程度。
5. 降糖药和胰岛素不得由健康管家自行调整。
6. 意识不清、抽搐、昏迷或无法安全吞咽等情况需要紧急升级。

当前审核状态：

- 6条全部“待复核”。
- 0条参与自动诊断或风险分析。
- 资料可以展示，但涉及数值、药物和紧急触发的规则必须经专业人员审核后才可启用。

### 22. 医学知识分级审核方案

不需要让医生逐字审核未来的所有内容，采用三级审核：

1. 来源审核：先确认国家卫健委、WHO、NICE 等资料是否可作为来源，一份资料只审核一次。
2. 批量知识审核：家族史、合理饮食、复查沟通等科普内容按主题批量审核。
3. 严格规则审核：会触发红色提醒、涉及具体数值、诊断标准、药物或急救措施的内容逐条审核。

还要区分：

- 允许展示：来源可靠、表达不误导。
- 允许参与自动判断：还要审核对象、时间、肯定/否定、单位、阈值、排除条件、升级动作和版本。

## 九、数据库和关键数据规则

核心表：

- `family_members`：家庭成员。
- `health_profiles`：稳定个人健康档案。
- `health_logs`：每日健康原话和结构化结果。
- `measurements`：血压、血糖、体温和体重。
- `medication_courses`：中药疗程。
- `medical_visits`：就医前、就医中和就医后记录。
- `conversation_messages`：小智对话消息。
- `health_documents`：检查资料和本地文件索引。
- `care_tasks`：复查、记录和持续照护任务。
- `emergency_contacts`：联系人。
- `check_in_schedules`：主动询问时间。
- `pending_actions`：需要二次确认的操作。
- `member_health_settings`：现代医学和中医守护设置。
- `health_analysis_runs` / `health_analysis_results`：分析批次和结果。
- `health_evidence`：分析证据原文和来源。
- `medical_rules`：规则编号、版本、风险和来源。
- `prevention_items`：有明确来源的预防事项。
- `health_log_revisions`：健康日志修改前版本。

必须长期保留的规则：

- `health_logs.raw_text` 保存原话，结构化结果不能替代原话。
- 重新分析采用新增批次，不覆盖历史分析。
- 患者转述医生意见必须标注来源。
- 电话、通知等动作先进入待确认状态。
- 原始医疗文件保存在本机。
- 未经审核的医学知识不能参与自动分析。
- 当前不提供删除健康记录接口；以后增加删除必须二次确认和审计留痕。
