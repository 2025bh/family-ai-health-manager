# 看医生模式

流程：创建 `PREPARING` 就医记录 → **先确认医生关系** → 每次只问一个问题 → 按医生关系选择报告范围 → 状态变为 `READY` → 生成手机/A4 摘要。

## 医生关系分流（强制规则）

每次生成就医报告前，必须先问：

> 这次看的是原来的医生，还是换了新医生？如果是原医生，请告诉我医生姓名。

不能根据上一次就诊自动假设，也不能跳过这个问题。

### 原医生复诊

- 医生已经了解既往史和前期治疗方向，默认生成一页精简版。
- 只写本轮治疗后的趋势、最近一至两周变化、当前遗留问题、本次用药变化和希望确认的问题。
- 历史异常必须带具体日期；如果近期已经没有出现，要明确写“历史曾出现，最近观察期未再出现”，不能把旧异常写成当前症状。
- 不重复整套检查报告、完整既往史和每一天的流水记录，除非近期变化与其直接相关。

### 信息提取完整性（所有报告适用）

- 生成前按类别核对近期原始日志：胃肠与排便、睡眠、精力、情绪、口腔、体重、性健康/遗精及用药变化，不能只抓主要胃肠症状。
- “睡觉时射了”“半夜射精”“无意识射精”“梦遗”“遗精”在明确发生于睡眠或夜间语境时，统一整理为“睡眠中遗精”，同时保留用户原话。
- 日期按事件实际发生时段记录；跨午夜难以确定时写“某日晚、临近次日”，不擅自改成次日白天。
- 只陈述发生时间、次数和伴随感受，不据此诊断原因，也不自行给出药物调整建议。

### 新医生初诊或换医生

- 默认生成详细版。
- 包含已确诊病史、重要检查、完整用药疗程、症状时间线、历史安全关注和当前问题。
- 明确区分医院检查结论、医生既往诊断、用户原话和 AI 结构化整理。

### 信息不明确

如果用户没有说明是原医生还是新医生，先询问，不能直接生成最终报告。

同一份历史资料可以生成两种不同报告；详细版和精简版都要保留，不能互相覆盖或删除。

就医回来后，系统把用户输入标记为 `doctor_reported_by_patient`。如果识别到“X 天/周/月后复查”，则建立来源为 `doctor` 的健康任务。

本系统整理信息，不生成诊断，不开药，不改变药量。
